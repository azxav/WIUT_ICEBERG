Fourteen kinds of traffic event, read off one fixed camera.

We turn hours of road CCTV into a short list of timestamped events (red-light runs, jaywalking, collisions, stalled cars, smoke) and a live score for how likely a crash is in the next five seconds.

    What the sample videos contain

    Before writing rules we measured the footage: how busy each scene is, which events occur and how long they last. Event length matters because the metric requires overlap of up to 70%, so a one-second error on a five-second event already fails.

    How it works

    A detector and tracker turn the video into trajectories once. Everything after that is geometry and timing on those trajectories plus a hand-drawn map of the scene, so the fourteen rules re-run in seconds while we tune them.

    Learned or rule-based

    Why rules on trajectories

    • There are a handful of labelled sample videos, far too few to train a fourteen-class video model.
    • Most classes are defined by geometry and signal state (crossing a line on red, driving against the lane direction), which rules express exactly and explain.
    • Boundaries score at tIoU up to 0.7, and rules give frame-precise starts and ends that we can shift per class.
    • Detection runs once; rules re-run from cached tracks in seconds, so tuning all fourteen classes is cheap.
    • Emitting a class that is absent from the test set costs a whole zero-F1 class, so rare classes use strict thresholds.
